## 探针从 49 个补回 80 个

### 发现

项目有 84 个探针文件，但 `build-v-probes.ps1`（权威执行清单）里只有 **49** 个。
也就是说 **35 个探针写了但从不运行**。

按「import 的生产类是否还存在」筛：全都还在。
所以是「覆盖有效功能但从不执行」，不是死代码 —— 删掉等于白丢覆盖。

逐个实测这 35 个：

| 结果 | 数量 |
|---|---|
| 全过 | **27** |
| 有失败 | 3 |
| 辅助类（无 main） | 5 |

27 个全过说明它们本来就有价值，只是从清单里掉了。已全部补回。

```
清理前  49 个，通过 55 / 61
清理后  80 个，通过 71 / 80
```

### 根因

自检脚本手写了一份探针清单副本，而不是读文件里那份。
于是「我跑了 61 个」和「文件写着 49 个」长期是两套东西。

现已改为**解析 `build-v-probes.ps1`**，不再手写副本。

## 尝试但放弃：`useHardSnap`（「左半边」观感）

上游 `neocursor-fix` 有个机制：对齐度 > 0.5 的角点时长置 0（瞬移到位），
于是形变体全堆在光标一侧，形成「前缘咬死、后缘拖出去」的半边效果。

实测后放弃，两个原因：

```
阈值      吸附角数   拉伸px   斜度px
关闭        0         8.26     4.06
0.3~0.707   2        11.58     2.11   ← 斜度反而变小
>0.707     0         8.26     4.06   ← 完全不触发
```

**1. 对齐度是离散的。** 纯轴向移动恒为 ±0.707，没有可调区间。
阈值只能一刀切：≤0.707 时 2 个角吸附，>0.707 时一个都不吸附。
想「只吸附 1 个角」在纯轴向移动下不可能实现。

**2. 吸附会压小斜度。** 2 个角同时吸附消除了同侧两角原本的时长差，
而「斜」正是由那个差产生的 —— 效果与目标相反。

要真做得先改 rank 体系（用移动向量而非角点残余位移），那是动核心物理。
推导过程已完整写在 `TrailCorner.java` 的注释里，避免下次重试。

## 安装

下载 `neovide-cursor-0.9.83.jar`，放到：
```
%APPDATA%\JetBrains\<IDE版本>\plugins\neovide-cursor-pawamamama\lib\
```
**先关闭 IDE**（它内存映射锁住 jar）。

如果你已经装了 v0.9.82，这个版本**观感上没有任何变化**，可以不更新。
