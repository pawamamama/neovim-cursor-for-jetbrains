## v0.9.73

从 **v0.5.1** 直接跳到 **v0.9.73**，中间 49 个提交、59 个文件、+6283 / −759 行。
这个版本的主要内容是**设置面板重构**与**一批用户实测反馈的缺陷修复**。

---

## 新增功能

### 光标尺寸可调（1–5px 宽 / 30–100% 高）
原来宽度写死 2px。现在可在「光标（尺寸 / 颜色效果）」组调节：
- **宽度 1–5px**：5px = IDEA 粗光标宽度（上限）。**静止时也保持这个宽度**
- **高度 30–100% 行高**：100% = 顶格，上限就是顶格，不能超过

实测说明：2px 宽也能看出颜色渐变，不需要为此加宽。

### RGB 纵向渐变（实验性）
拖尾纵向从「上端 = 拖尾颜色」渐变到「下端 = 蓝紫」。
**与「颜色」组的纯色填充互斥**：开启时纯色被覆盖，关闭后自动恢复。默认关。

原来只有启动参数 `-Dneovide.cursor.rgb=true`，界面上找不到 —— 现在是正常开关。

### 多光标时关闭辉光（性能开关）
光标 ≥ 2 个时把辉光层数强制归零，只保留拖尾拉伸形状。**全局生效，不随预设变化**。单光标不受影响。

### 设置页动画预览窗
行内打字 / 跨行换行两个预览窗，用**当前编辑器的真实字体**渲染，拖动滑块立刻变化。

### 顶行插件信息区
版本号、简介、GitHub 链接、检查更新按钮。

## 预设与按钮修复

### 「恢复为默认值」在自定义副本上是空操作
旧实现：在副本上点它，是把副本**当前的值再拷一遍给自己** —— 点完看不出任何变化。
而按钮文案写着「恢复为「基础 副本」默认值」，让人以为会回到「基础」。

现在：副本 → 回到它**派生自的那个内置预设**，并清掉副本名。
内置预设 → 回到自己的常量（原行为不变）。

**不会动颜色**（颜色由「颜色预设」独立管理），**不会动持久化项**（RGB / 宽度 / 高度）。

### 拖尾不透明度不随预设变化
`tailOpacity` 从 0.9.5 起就不在预设里。现在补入预设域，与 `glowOpacity` 同级。
顺带补入「淡出前保持时长」「淡出时长」两项。

### 卡密 / 恢复混用：两套清单不一致
自定义副本的快照存 24 个字段，而内置预设只写 9 个 ——
所以切到副本后点恢复，只有 9 个被拉回，剩下 15 个停在副本值。现已对齐。

## 缺陷修复

### 重启后设置丢失（最严重）
`loadState` 手写 23 条赋值，而 `State` 有 28 个字段。漏的 5 个是：
`diagLogging` / `multiCursorNoGlow` / `cursorWidthPx` / `cursorHeightRatio` / `rgbGradient`。

后果：写进了 XML，但**每次启动读回来时被丢弃**，值回到默认。
「RGB 勾了重启又没了」就是这条。

### 切自定义预设会把插件关掉
设置面板切自定义预设时没跳过运行环境开关，快照里的 `enabled=false` 会把整个插件关掉；
`hideNativeCaret` 还会改写 IDEA 全局配色方案（不可逆、会落盘）。
现已与 Tools 菜单路径统一，共用同一份跳过清单。

### 「纯平滑输入」每次重启被踢回「基础」
`animPresetBase` 的合法上界写死 `<= 1`，而预设数组有 3 项。已改为按数组真实长度校验。

### 打开工程但未打开文件时，改设置会覆盖已保存配置
`syncConfigToStateAndPersist` 无初始化守卫。CONFIG 还没从 State 灌满时点 Tools 任一开关，
会用编译期默认值覆盖持久化设置并立刻落盘。已加初始化守卫。

### 单行预览窗拉得很夸张
预览窗从不设 `charsMoved`，于是每帧走**像素兜底判据** ——
而那个判据在预览的 `width≈1.8px` 下会随字号漂移：
小字号判成短跳、大字号判成跨行。**同一个操作，结果随字号变**。
现已显式设置字符数，单行/跨行各走正确分支。

### 拖滑块预览窗不动，必须关掉设置再打开
`applyCursorSize()` 只在字号变化时被调用，改宽度/高度不重算尺寸。已修。
RGB 开关也从没传给预览窗，一并修好。

### 打字预览的顿挫与快速删除看不清
按权威数据重定节奏：
- **Nielsen 感知阈值**（HCI 基准）：0.1 秒是「感觉瞬时响应」的上限 ——
  间隔低于 100ms 时人眼会当成**连续运动**，看不出是「一步步」
- **本机 Windows 键盘实测**（`SystemParametersInfo`）：`KeyboardSpeed=31` ⇒ 30 字/秒 ⇒ 每字 33ms

原删除间隔 90ms **低于 100ms 阈值**，所以看到的是「一团连续在动的模糊块」。
现改为 130ms（阈值 + 30ms 余量），打字 170ms（真人是 200ms）。

### 新编辑器不同步全局设置
宽度 / 高度 / RGB 只在「点完设置面板」时读取，新开的编辑器一次都没读。已修。

### 光标变短后不居中
垂直锚点用了「光标自身高度的中心」，缩短时中心跟着上移 → 看起来从下往上被砍。
改为整行中线，上下各让一半。

### 块选区横向拉伸是单行的 2.5 倍
块选区的 offset 天然跨行差异大，用它算字符数必然被判成跨行 → 走长动画。已改为归一化判据。

## 内部重构（无行为变化）

### `createPanel()` 从 465 行降到 50 行
拆成 11 个 `buildXxxGroup(panel)` 方法。新增一组 = 写一个方法 + 加一行调用。

**踩过的坑**：组的渲染顺序不是源码书写顺序 —— `DialogPanel.group()` 是等回调跑完才挂到父容器，
所以内层组先挂、外层后挂。若按源码书写顺序调整调用位置，会导致全部控件索引偏移、探针串台。
现在用**组件树逐位比对**验证（79 条条目路径/深度/文本全同）。

### `SPECS[]` 数字下标改为按 key 查找（13 处）
原来是 `SPECS[11]` 这种硬编码，中间插入一项会让后面全部偏移且**编译期无提示**。

### ColorPanel 三向同步收进 `ColorPanelBinding`
`ColorPanel` 不是 DialogPanel 的绑定控件，平台不追踪 ——
每个面板要在 reset/apply/isModified 三个方向各写一遍。漏一个就静默失效。
现在登记一次，三个方向全有。

## 诊断与守门（开发用）

新增 8 个探针，总数达 53 个，全部经过**变异测试**验证「抓得住」：

| 探针 | 守什么 |
|---|---|
| `VLoadState` | `loadState` 覆盖全部 28 个字段（第四处拷贝） |
| `VDefaultFreeze` | 28 个默认值冻结（改默认值会让老用户观感静默变化） |
| `VAddSetting` | 加字段必须同步 FIELDS + copyFrom |
| `VColorBinding` | 登记数 == 面板上 ColorPanel 数 |
| `VPreviewBranch` | 预览窗必须显式设 charsMoved |
| `VPreviewRealtime` | 预览必须**真的**变（验几何/像素，不验字段赋值） |
| `VRestoreDefault` | 副本恢复必须回到派生自的预设 |
| `VTextFacts` | 面板文案里的可验证断言与代码一致 |
| `VReviewFixes` | 审查抓到的 5 条 bug |

诊断日志改为独立文件 `<config>/neovide-cursor-diag.log`，带 `[carets]` `[config]` `[preset]`
`[frame]` `[trail]` `[pick]` `[block]` `[error]` 前缀，便于按类别检索。

**fps 统计修正**：原来把「采样次数」当帧数，少算 15 倍（日志显示 6.8 实际 103），
且计数器是 static，开两个编辑器时表观翻倍。现在按「序号差 ÷ 时间差」逐 animator 计算。

## 安装

下载 `neovide-cursor-0.9.73.jar`，放到：
```
%APPDATA%\JetBrains\<IDE版本>\plugins\neovide-cursor-pawamamama\lib\
```
**先关闭 IDE**（它内存映射锁住 jar）。

升级注意：本次修改了若干默认值相关逻辑，但**默认值本身未变**（出厂仍是基础预设 / 粉色 / 2px / 顶格 / 平滑关）。
已用 `VDefaultFreeze` 锁住 28 个默认值，防止后续误改。
