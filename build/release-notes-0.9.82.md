## v0.9.82

从 **v0.9.73** 到 **v0.9.82**，9 个版本。
这一轮的核心是**手感对齐上游**——找到了「单行打字为什么画不出斜缎带」的根因，
并把斜度做成用户可调的独立参数。

---

## 最重要的修复：rank 塌缩

### 症状

单行打字时四边形是**规整矩形**，只有拉伸没有倾斜。
斜跳和换行才有缎带效果。

### 根因（一行代码）

四角排序用的「比自己小的有几个」计数：
```java
for (j) if (alignment[j] < alignment[i]) rank++;   // ← 相等时不计数
```

打字右移时四个对齐度是 `-0.71 / 0.71 / 0.71 / -0.71`——左边两角相等、右边两角相等，
于是双方拿到同一个 rank：

```
修前：TL=0  TR=2  BR=2  BL=0    只有 2 档
修后：TL=0  TR=2  BR=3  BL=1    4 档
```

rank 决定时长。修前 TL 与 BL 都是 110ms（同速）→ 左边缘永远垂直；
右侧同理 → 四条边全垂直 → **只能画矩形，斜度恒为 0**。

改成「稳定排序 + 索引 tiebreak」（上游四个 JS 版本一致做法），
结果与上游逐位一致：打字 `0 2 3 1`、删除 `2 0 1 3`。

## 新增：斜度可调（0–100）

此前只能通过「拉伸强度」间接调，而那个滑块的标签是「拉伸强度」，容易误解。

| 斜度 | 效果 |
|---|---|
| **0** | **纯矩形拉伸**（有拉伸、无倾斜） |
| 50 | 中等倾斜 |
| **100** | **完全斜 = 上游原版** |

实测（k=4.5、单行右移一字符、光标 2×32）：

```
斜度   四角系数                     拉伸      倾斜
0      0.86/0.86/0.32/0.32        5.84px    0.00px   ← 纯矩形
50     0.93/0.79/0.37/0.27        7.10px    2.02px
100    1.00/0.72/0.42/0.22        8.26px    4.06px   ← 上游原版
```

**斜度 0 仍有拉伸**（5.84px）——它只取消倾斜，不是取消形变。

实现原理：倾斜来自「同侧上下两角时长不同」，所以把同侧两角取平均即可消除倾斜，
而上下之间仍有梯度，拉伸保留。

斜度属于预设域：改它会派生副本，切预设回到该预设的值。

## 修复：Tools 菜单切颜色不生效

从「彩虹」切到「冰蓝」后光标仍是彩虹——因为 `applyColorPreset` 只写了两个 HEX，
没写 `rgbGradient`。设置面板那条路径早就同步了，Tools 这条漏了。

同时 `matchColorPreset` 也要比对 `rgbWash`，否则「彩虹」与「原版粉色」两个 HEX 相同，
会导致菜单里两个预设同时勾选。

---

## RGB 色相循环（颜色预设「彩虹（动态）」）

沿拖尾长度方向铺 2 个完整色相圈，整条色相随时间前移。
**不混色**靠单一 `LinearGradientPaint` 多色标实现（不叠加半透明层）。

参数照抄上游：饱和度 0.42、色相周期 4000ms、漂移周期 5000ms。
两个不同周期叠加，避免「每 4 秒整条同时跳一下」的机械感。

性能：8 光标 **246µs = 预算 3.1%**。

## 帧率：亚毫秒调度

原来 `computeNextDelay()` 返回 `int` 毫秒，帧率被钉在整毫秒档位
（8ms=125 / 6ms=166 / 5ms=200 / 4ms=250）。改为纳秒后，165Hz 想要的 6.06ms 也能表达。

实测（**裸睡眠循环**，非插件端到端）：

```
目标     实测      结论
125fps   124.5     精准
144fps   143.5     精准
165fps   129.9     达不到
240fps    91.7     达不到
```

所以只提供 **125 / 144** 两档。目标间隔小于 sleep 抖动时反而更不准。

同时排除了三个「优化」：`timeBeginPeriod` 无收益（调用前后都是 218~225fps）、
忙等反而更差（180 vs 221）、`parkNanos` 远差于 sleep（8.65ms vs 4.09ms）。

## 其他修复

### 老用户凭空多出「基础 副本」
斜度默认值 0.9.80 是 82、0.9.81 改成 100。若不迁移，老用户 State 停在 82 而预设声明 100，
会被判定「已修改」并自动派生副本。已迁移：82 → 100，用户真实值原样保留。

### 预览窗没跟着变斜
`AnimationPreview` 有自己独立的一套 `assignRanks`，还是旧版塌缩算法。
修了生产代码但预览没变——同一套算法两份实现。已统一。

### P4 技术债
- 删掉 25 行被无条件覆盖的死代码（读 IDEA 原生宽度算一遍再丢掉）
- 探针不再读恒为 0 的死数据（`polyX/polyY` → 真正的 `quads` 存储）
- HEX 颜色加校验（坏颜色会让光标变黑且返回 true）
- `RenderScheduler.loop` 加 try/catch（线程死后所有动画永久停摆且无信号）
- `syncConfigToStateAndPersist` 加初始化守卫（防用默认值覆盖用户设置）

## 诊断

新增 `[ime-skip]` 日志：输入法组合判据拦截时输出 skip 次数与两个坐标 API 的差值。
此前这条路径一个字节都不输出，无法区分「判据误拦」与「掉帧在别处」。

修复诊断日志的静态字段踩踏：多个编辑器共用 `lastSampleSeq`，
导致 85% 的采样行打出 `fps=?`。改为按 animator 身份隔离。
