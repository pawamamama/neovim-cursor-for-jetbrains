# Neovide Cursor 0.9.127 —— 多光标三异常修复

## 用户可见的变化

修复三个多光标问题（基础 / 纯平滑输入等预设均受影响）：

| 现象 | 修复后 |
|---|---|
| 列选多行按住右键，走到某一行（如中文注释行）时，**那一行的光标整个消失** | 光标不再消失；caret 按平台语义回绕到下一行时会**跟着出现在下一行**并继续有拖尾 |
| 同一场景走到某一行附近，**光标停在原地不动、辉光一直亮着** | 不再卡住；每个光标只跟自己的位置与辉光状态 |
| 多光标只剩孤立一个时，**它会跟着已消失的光标一起亮** | 辉光按光标隔离，孤立光标不再串亮 |

## 根因

- IntelliJ 261 的 `SelectionModel.getBlockSelectionStarts()` 是 **per-caret**（数组长度 = 光标数）；
- 虚拟空间关闭（默认）时，行尾按 → 会把 caret **移到下一行行首**，因此**同一行可以出现两个光标**；
- 旧实现用**行号**当拖尾 key（`-1000000 - lineNo`），同行两个光标 key 塌成一个、共用一条拖尾：
  - 一个槽位抢走拖尾 → 另一行没有拖尾（光标消失）；
  - 共享拖尾每帧被两个目标写入 → 最后一次移动时刻每帧刷新 → 保持期永不过期（卡住 + 辉光常亮）。

## 修复内容

- 多光标 / 块选区每个槽位改用 **caret 对象身份**做 key（唯一、跨帧稳定）；
- 目标点改用该光标自己的活动端（`getVisualPosition()/getOffset()`），同时修正向左扩选落在锚点侧的问题；
- 槽位数改为 `max(caret 数, starts 数)`，平台选区 API 失败时不再把多光标误判成单光标；
- 主光标拖尾（残影锚点）在 >64 光标时兜底取第一条；
- 行号 key 仅保留为旧平台兜底；单光标路径行为不变。

## 安装

用户配置无需改动（本版没有默认值变更）。
