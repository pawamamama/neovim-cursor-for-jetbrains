# 界面国际化计划（i18n）

> 目标：把**用户可见的界面文案**抽到资源包，英文为默认、中文覆盖。
> 日志、注释、异常 message、探针自身输出一律不动。
> 基线：`a99c342`，工作区只有未跟踪的 `build/night-run-report.md`。

### 1.2 官方文档（网络受限，改用字节码实测）

`plugins.jetbrains.com` 被本机网络策略拦截，无法取官方页面。
改用**本机 idea-libs 的字节码**作为权威依据：

- `com.intellij.DynamicBundle` 有 `DynamicBundle(Class<?>, String)` 构造器，
  `getMessage(String, Object...)` 继承自 `com.intellij.AbstractBundle`；
- `org.jetbrains.annotations.PropertyKey` 存在，`resourceBundle()` 可指定包名；
- `AbstractBundle.messageOrDefault(ResourceBundle, String, String, Object...)` 可安全取缺失键；
- `DynamicBundle.getLocale()` → `LocalizationUtil.getLocale()` →
  `LocalizationStateService.getInstance()`；取不到服务时回退平台默认（英文）。

### 1.3 关键实测（原型：`build/i18n-proto/`，验证后删除）

| 场景 | 结果 |
|---|---|
| `DynamicBundle` + 无语言包 headless | **永远 root（英文）**，`-Duser.language=zh_CN` 也无效 |
| `DynamicBundle.getResourceBundle(cl, path, Locale.ENGLISH)` | **无视传入 locale**，仍按平台结果取包 |
| 纯 `ResourceBundle.getBundle(path, Locale.ENGLISH, cl)` | 中文系统上**取到 `_zh_CN`** |
| 纯 `ResourceBundle` + `getNoFallbackControl(FORMAT_PROPERTIES)` | `en → root 英文`，`zh_CN → _zh_CN 中文` ✅ |

**为什么第三条会这样**：JDK 默认 `Control` 会在 root 之前插入
`Locale.getDefault()` 作为 fallback locale。中文 Windows 上即使显式传 `Locale.ENGLISH`，
候选链是 `[en] → [zh_CN] → root`，于是先命中 `_zh_CN`。
必须用 `getNoFallbackControl` 关掉这条回退。

### 1.4 设计决定（偏离提示词的 DynamicBundle，理由在此）

**决定：用 `java.util.ResourceBundle` + `getNoFallbackControl`，
locale 优先取平台的 `LocalizationStateService.getSelectedLocale()`，取不到再回退
`Locale.getDefault()`。**

```
生产（IDE）：LocalizationStateService 非空 → 跟随 IDE 语言设置（语言包）
探针（headless）：服务为空 → Locale.getDefault() → 两套 locale 可验证
```

不用 `DynamicBundle` 的原因（实测事实，不是偏好）：

1. 它在无语言包的 headless 环境里**永远英文**，`-Duser.language` 无效 →
   两套 locale 门禁会变成「跑两遍同样的英文」，**验证不到中文**；
2. 它按语言包 EP 决定 locale，而本插件的 `_zh_CN.properties` 是**随插件自带**的，
   不需要语言包；用 `LocalizationStateService` 已能正确跟随 IDE 语言设置；
3. 它的 `getResourceBundle(loader, path, locale)` 也**无视显式 locale**，
   没有可测试的注入点。

保留的部分：`AbstractBundle.messageOrDefault` 做格式化（与平台同一套 MessageFormat 语义），
`@PropertyKey` 标注 key 契约。

## 三、资源包与代码

```
src/main/resources/messages/NeovideCursorBundle.properties        英文（root，默认）
src/main/resources/messages/NeovideCursorBundle_zh_CN.properties  中文
src/main/java/.../ui/settings/NeovideCursorBundle.java            门面
```

门面规则：

- `message(key, params...)`：`AbstractBundle.messageOrDefault(bundle, key, key, params)`；
  缺键时界面显示 `settings.xxx`（可见、不崩），由探针守门键完整性；
- `currentLocale()`：平台服务可用则用它，否则 `Locale.getDefault()`；
- `resourceBundle()`：每次按当前 locale 取包（`ResourceBundle` 自带缓存），
  不自己缓存，避免语言切换后拿到旧包；
- 所有 UI 文件只依赖这个门面，不直接调 `ResourceBundle`。

Key 命名：`区域.用途`，区域为 `settings.*` / `info.*` / `action.*`；
预设名用 `settings.preset.anim.<下标>` / `settings.preset.color.<下标>`（按下标，不按中文名）。

## 五、门禁与打包

1. **门禁运行时 classpath**：`$probeDir;$classesDir;$resDir;$cp`，
   其中 `$resDir = <repo>\src\main\resources`。否则探针加载不到 properties。
2. **两套 locale**：用 `JAVA_TOOL_OPTIONS=-Duser.language=en -Duser.country=US`
   与 `-Duser.language=zh -Duser.country=CN` 各跑一次全量门禁。
3. **打包**：`offline-build.ps1` 现在只把编译产物与 `plugin.xml` 塞进 jar。
   必须先把 `src/main/resources` 全量拷进 `$classes`，再用模板 `plugin.xml` 覆盖，
   否则真机启动时资源包缺失。

## 六、已知缺口（明确报告，不假装完成）

1. **`plugin.xml` 菜单标题**仍是中文（`Neovide 光标：动画预设` 等）。
   平台对 plugin.xml 的本地化需要 `<resource-bundle>` + `%key`，属于另一层机制；
   本轮范围是设置面板，未改 plugin.xml。
2. **Tools 菜单里的内置预设名**由 `CursorPresets.ANIM_PRESETS[i].name()` 提供，
   本轮只把**设置面板下拉框**的显示名本地化；菜单项仍是中文。
3. **`CustomPresets.nameError`** 返回的中文校验原因仍会显示在对话框里（settings 层）。
4. 新建副本的默认名后缀 `" 副本"` 属于**用户数据**，未翻译。

5. **`CUSTOM_COLOR_LABEL` 现在没有引用**（面板改用 bundle 的 `settings.item.customColor`）。
   它仍在 `settings/CursorPresets.java`，属 settings 层，本轮不删；后续清理时可删。
6. **平台 API 标注 `@ApiStatus.Internal`**：`com.intellij.AbstractBundle` 与
   `com.intellij.l10n.LocalizationStateService` 在 252 平台 jar 里都是 Internal。
   本机没有 2024.2（since-build=242）的平台构件，**无法核实这两个方法在 242 是否存在**；
   建议后续把 Plugin Verifier 的 2024.2 校验接进交付门禁。
7. **英文值里三处 ASCII 单引号**（`preset's` ×2、`glow's`）当前都**无参数调用**，
   MessageFormat 不介入，所以原文完整；将来给这些键加 `{0}` 时必须写成 `''`，
   否则英文界面会少一个撇号。
8. **`verify` 的最终形态**：两条门禁（en / zh）都跑完整 110 个可执行探针；
   113 个 `V*.java` 里 3 个是辅助类（`V0Env` / `VUi` / `VFields`）。

以上各条都会在交付报告里逐条列出，不写成「已全部完成」。
