## 二、现状的两个真问题

### 问题 A：色相循环成了死代码

0.9.85 把 `rgbEnabled` 开的行为从「色相循环」改成「双拼渐变」后：

```
buildRgbWashPaint        -> 零调用（只剩定义）
9 个常量 + 2 个数组字段   -> 全部无人读
约 140 行代码            -> 死代码
```

**但「彩虹（动态）」颜色预设还在**。选中它 -> `rgbGradient = true` -> 走**双拼**。
用户看到：选「彩虹」-> 光标变成粉色双拼。**功能对不上名字。**

### 问题 B：两个入口打架

| 功能 | 入口 |
|---|---|
| 双拼 | 光标设置「光标渐变」复选框 |
| 色相旋转 | 同上 + 颜色预设「彩虹（动态）」 |

同一个字段 `rgbGradient` 被两处写，语义却不同。
这是纪律四-D「一个字段承担两个职责」的翻版。

## 三、我的决策

### 决策 1：`rgbGradient` 只表示「有没有渐变」，不再表示「哪种渐变」

```
rgbGradient = false  -> 纯色
rgbGradient = true   -> 按 washStyle 决定是双拼还是旋转
```

引入 `washStyle`（存在 State 里，不走颜色预设）。

**为什么不放颜色预设**：
用户约束 2 说「彩虹是独立颜色预设」——但那是**颜色的选择**，不是**渲染方式的选择**。
颜色预设管「用什么颜色」，`washStyle` 管「怎么画」，两者正交。

### 决策 2：色相旋转重写为**纯旋转**

```
旧（错）：沿长度铺 2 圈 -> 上端蓝、下端紫同时存在
新（对）：整条同一色相，色相值随时间 0->360 循环 -> 整根光标一起变色
```

依据：上游 `hue-rotate(-360deg)` 就是整条同时转。
周期用上游的 **4000ms**。

### 决策 3：「彩虹（动态）」预设改为**纯颜色选择**，去掉 rgbWash

它现在的两个 HEX 是 `#FFC0CB/#FFC0CB`（等于粉色）。
动态与否由光标开关 + washStyle 决定。

这样：
- 颜色预设全部退化为「两个 HEX」，正交性回归
- `rgbWash` 字段可以删掉，`matchColorPreset` 也不用再比它
- Tools 菜单不再有会「偷偷开动态」的预设

### 决策 4：`targetFps` 移到总开关组

它已经是持久化项（五处链路全通），位置从「光标」组移到总开关区，
与「常驻刷新」「多光标时关闭辉光」同级。
