## 1. 候选功能：接管范围扩到「除终端外的一切输入框」

用户原话大意：
> 「多光标时候直接除了终端不能接管所有输入框 —— 我发现 git 提交写提交文案的时候这个能用，很舒服」

**需求拆解**：

| 项 | 现状 | 目标 |
|---|---|---|
| 主编辑器 | 接管 | 接管 |
| 控制台 / Build / Run 输出 | 接管（静态光标，无拖尾） | 保持 |
| **提交信息框（Commit Message）** | **用户实测能用** | 明确保留 + 写进验收 |
| 搜索框 / 重命名框 / 其它 TextField | 未知 | 待查：`EditorTextField` 类控件是否也挂得上 |
| 终端 | **不接管**（终端自己画光标，接管会双光标） | 保持排除 |

**技术入口**：`NeovideCaretManager.install()` 现在按 `EditorFactory.getAllEditors()` 挂载；
Commit 框是 `EditorTextField`（本质也是 Editor），所以天然能用。
要找的是：哪些 `JTextField`（非 Editor）也想接管 —— 那是**另一套绘制**，成本高，先不做。

**结论**：把它写成「验收项」而不是「新功能」：提交框、控制台、主编辑器三者都要有拖尾，终端没有。

## 2. VS Code 上游原版观感（用户对比结论，重要）

用户原话大意：
> 「好像没有扩散但是有缎带效果，而且是快速输入删除，是斜着的缎带就是梯形光标，顶部长、尾部短，
> GUI 绘制真的舒服。而且他那个和原生光标……不显示，不动的时候不显示，只有短短的缎带效果」

**拆成 5 个可实现的观感特征**：

| # | 特征 | 我们现在的状态 | 判断 |
|---|---|---|---|
| 1 | **没有辉光扩散**（sharp edges，几乎看不到 blur） | 默认 `shadowBlurFactor = 0.2`（约 14px 扩散） | 差异：我们更“糊” |
| 2 | **斜着的缎带**（四角不同步 → 矩形被剪成平行四边形/梯形） | 已实现（rank 0–3 四档时长），但默认 4.5× 可能不够陡 | 需要更陡梯度才有“斜”感 |
| 3 | **梯形：顶部长、尾部短** | 我们的梯度是「后缘慢、前缘快」，视觉上应该相反？ | **需要真机对比确认**（可能是朝向差异） |
| 4 | **静止时不显示光标本体，只剩一截短缎带** | 我们静止时画一个完整的 2px 光标（因为隐藏了原生） | 差异明显：这是“残影感”的来源 |
| 5 | **GUI 绘制顺滑** | 我们是 canvas + 每帧 fillPolygon，125fps | 需要帧时间实测对比 |

> ⚠️ 特征 3 我没看懂「顶部长尾部短」具体指哪个方向 —— **要用户画一下或截个图**，不能猜。

**可能的实现方向（先记着，别急着做）**：

- 特征 1：把 `shadowBlurFactor` 降到 0.10–0.15（已有「辉光锐度」滑块，用户自己拉即可）；
- 特征 2：把 `stretchRatioK` 从 4.5 提到 6–8（同样有滑块），四角时长差变大 → 更斜；
- 特征 4：**这是结构性改动** —— 静止时降低本体不透明度 / 只画尾部一段。与「隐藏原生光标」互斥：
  如果原生光标在，静止时有原生光标，缎带收掉即可（**这就是上游 Lesson #19 叠加模式**）；
  如果隐藏原生，静止时必须画本体，否则看不见光标。→ **再次指向 D 组议题**。

## 3. 用户当前的两个疑问（待诊断）

### Q1「我不知道那个是持久配置」

- **19 个参数全部持久化**，存在 `%APPDATA%\JetBrains\IntelliJIdea2026.1\options\NeovideCursorSettings.xml`；
- 「总开关那组」只是**语义分层**（改它不会让预设变「已修改」），不是另一套存储；
- 面板上所有改动都要点「应用 / OK」才落盘；点「取消」不落盘。

### Q2「预设改了，动态条真的生效了吗？动画不跟手，少一拍」

**先分清两件事**：

| 现象 | 可能原因 | 验证方法 |
|---|---|---|
| 预设改了但看不出变化 | ① 没点「应用」；② 选的是同一预设；③ 改的字段不在该预设里 | 把「辉光层数」改成 1、「辉光不透明度」改成 0 —— 这种极端值一定看得见 |
| 动画「少一拍」 | ① **常驻刷新被关掉了**（面板里那个开关；关掉后空闲降频到 120ms，停手后第一次操作慢一拍）；② **隐藏原生光标**（拖尾就是本体，任何一帧延迟都可见）；③ `shortAnimationLength = 0.11` 比上游默认长 → 视觉上“追尾更久” | 见下方 A/B 三组 |

**A/B 三组（建议按顺序试，每组只看“少一拍”有没有改善）**：

```
A 启用辉光关掉？不用。只做：确保「常驻刷新」勾选 → 应用 → 重启 IDEA
B 取消「隐藏原生光标」→ 应用  （原生光标跟手，拖尾只做装饰；这是上游推荐模式）
C 把「短动画时长」从 0.11 降到 0.08 → 应用
```

> 若 **B 组明显改善** → 说明问题在“拖尾当本体”，那是 D 组议题，需要用「分离」方案 + 唤醒路径改造解决；
> 若 **A 组改善** → 单纯是常驻刷新被关了（我把菜单项挪进面板了，你可能没找到它在哪）。

## 4. 结论 / 下一步

1. **不要**同时改代码和调参数 —— 先定“手感基线”；
2. 用户先做 A/B/C 三组，回一个结论；
3. 我按结论决定：是改默认值、改唤醒路径、还是做 D 组分离；
4. 「除了终端接管所有输入框」记为验收项，不单开功能；
5. 「梯形/斜缎带/静止不画本体」记为观感目标，**等用户给一张截图或画个方向图**再动手。
