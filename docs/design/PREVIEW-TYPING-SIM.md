# 预览窗要「像真实打字 / 删除」——方案（2026-10-28）

> 用户原话：「窗口预览调整，实时预览有了可就不是真实打字删除的感觉，
> 这轮计划一下弄个方案但是别切到计划模式」
>
> 本文只出方案，**本轮不实现**。

---

## 一、先看现状（代码事实，不是印象）

两个预览窗都在 `ui/settings/AnimationPreview.java`，由两个 `javax.swing.Timer` 驱动：

```
physicsTimer  FRAME_MS       → step()    物理积分（弹簧每帧推进）
actionTimer   actionInterval → advance() 推进「场景」
```

**单行预览（`Mode.INLINE`）已经内置完整循环**（`advanceInline()`，:552-604）：

```
phase 0  逐字打字（每次 +1 字，间隔 TYPE_MS）
phase 1  打完停 HOLD_AFTER_TYPE_MS（2 秒）
phase 2  逐字退格（间隔 BACKSPACE_MS）
phase 3  停 SWITCH_PAUSE_MS，切换中/英文文本，回到 phase 0
```

每次推进都设 `pendingCharsMoved = 1`，走**短跳分支**（`TrailCorner.jump`），
这正是真实编辑器里打/删一个字符时的分支。

**跨行预览（`Mode.CROSS`）** 演示「行尾 → 回车到下一行行首 → 退格回上一行」，
两行之间来回拉斜向缎带。

### 所以「不像真实」到底差在哪

代码里能确定的差异只有这几条：

| 差异 | 说明 |
|---|---|
| 节奏是常量 | `TYPE_MS` / `BACKSPACE_MS` 固定间隔，真人打字是不均匀的（快慢、顿挫） |
| 不看键盘 | 预览是**自己演**，你在设置页里按键它不会响应 |
| 文本固定 | 中英文各一条固定串，不是你在编辑器里真正打的内容 |
| 环境简化 | 预览用自己的字体/行高/光标宽度推导，不是主编辑器真实的度量 |

用户说的「不是真实打字删除的感觉」**具体指哪一条，代码判断不出来**，需要确认（见第四节）。

## 二、四种可能的需求，实现代价差很多

| # | 理解 | 做法 | 代价 | 风险 |
|---|---|---|---|---|
| A | **节奏不像真人** | 给 `TYPE_MS` / `BACKSPACE_MS` 加随机抖动（±30%），偶尔插入一个长停顿；再加一个「节奏：慢/正常/快」下拉 | 小（改 `advanceInline` 的 `setInterval` 计算） | 低 |
| B | **想自己动手打** | 让预览窗可获得焦点，`KeyListener` 拦截字符/退格，驱动 `typed` 与 `pendingCharsMoved` | 中（焦点管理、输入法、与面板方向键冲突） | 中：抢焦点会让设置页键盘导航失效 |
| C | **想更快看到效果** | 把「打完停 2 秒」缩短，或让整个循环速度可调 | 小 | 低 |
| D | **想更接近真实编辑器** | 预览直接复用主编辑器的 `FontMetrics` / 行高 / 光标宽度（而不是自己按字号推算） | 中 | 中：无主编辑器时要有回退 |

---

## 三、推荐

**先做 A + C（合起来算一件事：节奏可调 + 抖动），B 和 D 单独评估。**

理由：
- A/C 不碰焦点、不碰平台输入法，改动集中在 `advanceInline` 的 3 个 `setInterval` 调用；
- B 的收益看起来最直接（「我能自己试」），但它会让预览窗抢走键盘焦点，
  设置页的方向键/回车导航会失效 —— 这是一个**新的**问题，不一定比现在好；
- D 属于「预览与生产同源」这条老纪律（CLAUDE.md 陷阱 6）的延伸，
  但它依赖「当前有主编辑器」，没有时要回退，属于独立一轮。

**建议的形态（若采纳 A+C）**：

```
预览窗下方加一行：  节奏 [慢 | 正常 | 快]     ☑ 加入停顿（更接近真人）
```

- 「节奏」只缩放 `TYPE_MS` / `BACKSPACE_MS` / `HOLD_AFTER_TYPE_MS` 三者的基数；
- 「加入停顿」开启时，每 5~9 个字符随机插入一次 200~500ms 的停顿（用固定种子的伪随机，
  避免每次重绘都不一样，也让探针可复现）；
- 默认值保持现在的观感（正常 + 不加停顿），**不改变老用户看到的样子**。

---

## 四、实现前必须先确认的问题

代码无法判断用户要的是上面哪一种，**实现前必须问清楚**（纪律四-I）：

1. 你说的「不像真实」，是**节奏太机械**，还是**想自己动手敲**？
2. 如果是想自己敲：你能接受「点一下预览窗才能开始打字」吗（它必须抢焦点）？
3. 现在的「打字 2 秒 → 逐字删」这个循环你希望保留吗？

---

## 五、若采纳 A+C，验收怎么做

1. **守门探针**：新建 `VPreviewRhythm`，断言
   - 节奏档位改变后 `actionInterval` 按预期缩放（读预览窗的 interval，不读影子变量）；
   - 「加入停顿」开启时，推进 N 步期间至少出现一次 > 200ms 的间隔，且**可复现**（同种子同结果）；
   - 关闭时与现在的行为**逐帧一致**（回归保护）。
2. **手动验收**：三个节奏档各看 10 秒，确认慢档下能看清单字符拖尾、快档不糊成一片。
3. **不回归**：`VPreviewParity` / `VPreviewRealtime` / `VPreviewBranch` 必须仍然绿
   —— 它们守的是「预览与生产同源」「参数实时生效」，本次改的是节奏，不该影响它们。
