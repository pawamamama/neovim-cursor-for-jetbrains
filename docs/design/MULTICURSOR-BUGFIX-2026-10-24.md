## 二、问题 1：块选区不产生多个 Caret

### 根因

**Alt+鼠标拖拽走的是完全不同的平台机制。**

| 操作 | 平台行为 | getAllCarets() 返回 |
|---|---|---|
| Alt+点击 / Alt+Shift+点击 | 真正的多光标 | **N 个** |
| **Alt+鼠标拖拽（列选）** | SelectionModel.setBlockSelection() | **1 个** |

块选区是「1 个 caret + 1 个矩形选区」，列信息在
getBlockSelectionStarts() / getBlockSelectionEnds() 里，**不在 caret 列表里**。

我们的多光标基于 getAllCarets()，所以块选区永远只看到 1 个 ——
这正是用户说的「只有鼠标拖拽的地方有一个」。

### 修法

新增 CaretAnimator.collectTrailTargets()：

- **块选区优先**：它有 N 行就必须画 N 条拖尾，即使 carets 只有 1 个
- 否则走 getAllCarets()（Alt+点击等多光标）
- 上限 64（防全选文件爆掉）

两者在平台上互斥，不会同时存在。

## 三、问题 2：光标宽度用错了 API

### 根因

**EditorSettings.getLineCursorWidth() 返回的是相对倍率，不是像素。**

- IDEA 默认 = 1（普通光标）
- 用户设「粗」= 2 或 3

我们直接把它当像素用 → 用户设粗光标时，**我们画 2px，IDEA 画 10px**。

### 修法

改用 **EditorUtil.getDefaultCaretWidth()** —— IDEA 自己的换算方法，
它把「倍率 × 字体度量」算成真实像素宽度。失败时退回倍率。

## 四、代码审查发现的 2 个缺陷

### 缺陷 A（严重）：IdentityHashMap + Long.valueOf → 内存泄漏

块选区用 offset 当 key，每帧 Long.valueOf(offset)。

**Long 只在 -128~127 有缓存**，offset 通常远超 → 每次 new 一个。
IdentityHashMap 按**引用**判等 → 认为「新 key」→ 每帧新建 SpringTrail，
旧条目永远清不掉（内存泄漏 + 拖尾重复）。

**修法**：改 HashMap + Integer。
（Caret 未重写 equals/hashCode，HashMap 下天然是引用判等，与 IdentityHashMap 等价。）

### 缺陷 B（中等）：清理依赖数量比较

```java
if (trails.size() > activeTrails.size()) {   // ← 两种场景失效
    trails.entrySet().removeIf(...);
}
```

- **平台合并光标**：一增一减、数量不变 → 永不进清理分支
- **块选区行数不变但内容换了** → 同样不进

**修法**：无条件按帧号清理（O(n)，n ≤ 64）。
