## 二、修复的 bug（本轮全部）

### 光标宽度（0.9.17）

**问题**：保留原生光标时出现「两个光标」。

**根因**：`EditorSettings.getLineCursorWidth()` 返回的是**相对倍率**（默认 1，粗光标 2~3），
被当成像素用 —— 用户设粗光标时我们画 2px、IDEA 画 10px。

**修法**：改用 `EditorUtil.getDefaultCaretWidth()`（官方像素换算）。

### 块选区中文失效（0.9.18）

**问题**：块选区输入中文后「只有最后一行动」。

**根因**：块选区的 key 用了 `offset`。输入中文后每行 offset 都变 → key 变 → 当成新光标重建。

**修法**：key 改用**行号**（行内编辑时不变）。

### 辉光串扰（0.9.18）

**问题**：多光标快速输入时「撕裂感」。

**根因**：`maxOffset` 取所有光标的全局最大值 → 一个在动会拉长所有光标的淡出。

**修法**：按相邻行分组，组内共享、组间隔离。

### 块选区拖尾长度不一致（0.9.18）

**问题**：「第一行拖尾长，最后一行短」。

**根因**：块选区错误地用了 `startFrom`（复制源形状，但位置不同 → 相对目标点错位）。

**修法**：块选区各自吸附。

### 块选区加速度不均（0.9.21）

**问题**：「加速度还是不均匀」。

**根因**：每行独立算 `charsMoved`，而 `TrailCorner.jump()` 按它分两个分支（短跳 / 跨行），时长差 2 倍。
造成「有的行短跳、有的行跨行」。

**修法**：块选区所有行共享同一个 `charsMoved`。

### 选区跟随（0.9.22 → 0.9.24 → 0.9.27，改了三轮）

**问题**：`Ctrl+Shift+→` 扩展选区时，拖尾不跟。

**这轮我错了两次，如实记录**：

| 版本 | 我的判断 | 结果 |
|---|---|---|
| 0.9.22 | `lead` 是活动端 | ❌ 错，单行冻结 |
| 0.9.24 | 快速路径也要用 lead | ❌ 错，仍冻结 |
| 0.9.27 | **加日志后实测：`getVisualPosition()` 才是活动端** | ✅ 对 |

**实测数据**（20193 条日志）：
```
vp = 29:17 → 29:23 → 29:38    ← 在变（活动端）
lead = 29:12  恒定             ← 固定锚点
```

### 块选区向右扩展失效（0.9.31）

**问题**：块选区「向左扩正常、向右扩失效」。

**根因**：块选区有两个数组，**各管一个方向**：
- `blockStarts[]` = 左边界（向右扩时不动）
- `blockEnds[]` = 右边界（向右扩时增长）

我一直用 `blockStarts`，所以向右扩必然不动。

**修法**：按 `caretOffset` 与 `leadOffset` 的关系判断方向，选对应数组。

## 四、安装

⚠️ **必须先关闭 IDEA，并且清空 `lib` 目录。**

> **为什么**：`lib/` 下所有 jar 都会被当插件扫描。
> 2026-10-24 我曾因此误判「已安装」—— 实际 `lib` 里堆了 12 个 jar，
> IDEA 加载的是 0.9.14 而不是我以为的新版。
