# 死探针清理（0.9.83）

> 用户要求「清理死探针」。实际做下来发现：**没有死探针，只有被遗忘的探针**。

---

## 一、发现过程

判据：`build-v-probes.ps1` 是权威执行清单，不在里面的探针 = 从不运行。

84 个探针文件，清单里只有 **49** 个 → **35 个从不运行**。

### 但不能直接删

按「生产类是否还存在」筛一遍：这些探针 import 的
`settings.*` / `ui.*` / `core.*` 全都还在。

那就是**覆盖有效功能但从不执行**，不是死代码。删掉等于白丢覆盖。

### 实测决定

逐个跑这 35 个：

| 结果 | 数量 |
|---|---|
| 全过 | **27** |
| 有失败 | 3（VReset2 / VSepBound / VSleep） |
| 辅助类（无 main） | 5（V0Env / VUi / VFields 等） |

**27 个全过** —— 它们本来就有价值，只是从清单里掉了。

---

## 二、做法：补回清单，不删除

把 30 个有 main 的探针全部加回 `build-v-probes.ps1`（另 5 个是辅助类，不需要）。

```
清理前  清单 49 个，通过 55 / 61（我用临时清单跑的，不是文件里的）
清理后  清单 80 个，通过 71 / 80
```

覆盖度从 49 提到 80，通过数从 55 提到 71。

---

## 三、为什么会出现这种情况

根因是**我一直在用临时命令里的清单，而不是文件里的**。

之前的自检脚本里手写了一个 `$mains` 数组，每次都复制粘贴，
所以「我跑了 61 个」和「文件里写着 49 个」是两套东西。
文件那份从某次编辑后就再没被读过了。

**教训**：自检脚本必须**从文件读清单**，不能手写副本。
现在 `build-v-probes.ps1` 是唯一权威，自检也改成解析它。
