## 二、每个提示词必须含的五样

### 1. 前置检查（不通过就停）

```bash
git status --porcelain
git log --oneline -3
```

只允许 `?? build/night-run-report.md` 这一行未跟踪文件。

### 2. 陷阱记录检索（本项目**没有** `/trap` 命令）

替代物是三个文件，让执行会话读并贴命中原文：

- `CLAUDE.md` 第五节「十四类陷阱」
- `docs/WORK-DISCIPLINE.md`（四-J 可维护性、四-L 只问产品决策）
- `LESSONS.md` / `docs/NEXT-STEPS.md` 的相关章节

**没命中就明确写「三处均未命中」，不许跳过。**

### 3. AC 格式（不是「门禁绿」，是「行为对」）

```
AC-NNN: <可观察的行为，一句话>
- 场景：<起始条件>
- 动作：<单一触发>
- 期望：<可观察的结果>
- 禁止副作用：<这件事不能同时发生>
- 验证：<用什么证明>
- 优先级：必需 / 重要 / 可选
```

**「门禁 ALL PASS」只能当辅助证据，不能当唯一 AC。** 回归 bug 就是在门禁全绿时复发的。

### 4. 禁止话术清单（原样贴进每个提示词）

```
以下说法一律不允许出现在报告里：
- 「这是预先存在的问题」→ 必须 git stash 后跑同一命令，贴两次输出
- 「为了通过测试，我调整了断言」→ 一律不接受
- 「探针过期了 / 断言写错了」→ 只有上游明确列出时才成立
- 「先跳过这个测试」→ 没有「先」
- 「应该没问题 / 理论上是对的」→ 不算证据
- 「已修复」→ 没贴验证输出的改成「已改动，未验证」
- 「顺带修复了 XXX / 顺便优化了一下」→ 白名单外的一切改动都是违规
- 「其余改动都是无关紧要的格式调整」→ 白名单外任何字节变化都要说明并获准
```

### 5. 白名单 + 停下来问（≥5 条具体触发条件）

**白名单的教训（三次都栽在这里）：**

| 漏了什么 | 后果 |
|---|---|
| `build-v-probes.ps1`（新探针必须注册进 `$mains`） | 探针写了但从不运行 |
| `CLAUDE.md` / `START-HERE.md` / `NEXT-STEPS.md` 的探针数字 | `VDocCheck D-2` 会红 |
| `CursorDiag.java`（字符串和 `emit()` 都在那） | 白名单划在 `CaretAnimator`，但真正要改的地方不在这 |

**写白名单前先问自己：这个任务要动的字面量，物理上存在哪个文件里？**

## 三、怎么判定执行会话的报告（八条，逐条查）

| # | 检查 | 不合格长什么样 | 处理 |
|---|---|---|---|
| 1 | 陷阱记录检索 | 没贴原文 | 打回 |

| 8 | 探针断言 | 有任何一条被删/放宽 | 回退重做 |

**第 5、8 条是红线，不商量。**
