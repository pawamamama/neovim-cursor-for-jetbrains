# 会话交接协议（决策会话 ↔ 执行会话）

> 2026-11-04 建立。适用本项目所有非平凡改动。
> 全局背景见 `D:\claudework\_templates\claude-workspace-workflow.md`；本项目五步见 `docs/WORKFLOW.md`。
> 本文件只回答一件事：**两个会话之间怎么交接，才不会互相猜。**

---

## 一、两种角色

| | 决策会话 | 执行会话 |
|---|---|---|
| 目标 | 决定做什么、怎么验收 | 按提示词做完、给出证据 |
| 可以改 | `docs/sessions/.../PROMPT.md`、决策文档 | `src/`、`tools/`、`docs/sessions/.../REPORT.md` |
| 不可以改 | 生产代码、探针断言 | 验收标准、需求边界 |
| 必须产出 | 一份自包含的 PROMPT | 一份带数字的 REPORT |
| 遇到歧义 | 问用户（给选项） | 停下，在 REPORT §6 写清，不硬做 |

**判据**：执行会话发现「提示词里的验收标准做不到」时，正确动作是**停**，
不是改标准去迁就实现。

---

## 二、一轮循环

```
用户提需求
   ↓
决策会话：侦查 → 写 PROMPT → 用户确认
   ↓
执行会话：读 PROMPT + CLAUDE.md → 干活 → 写 REPORT
   ↓
用户实机验证 → 把结论补进 REPORT §7
   ↓
决策会话：读 REPORT（关键结论自己跑命令复核）→ 下一份 PROMPT
```

每一轮一个目录：`docs/sessions/<YYYY-MM-DD>-<主题>/`。
验收通过或明确作废后，整目录移到 `docs/archive/sessions/`（只挪不删）。

## 三、PROMPT 模板（决策会话写）

必须自包含：执行会话不读上一轮对话。

```markdown
# <主题> 施工提示词（YYYY-MM-DD）

> 状态：待执行 / 执行中 / 已执行 / 已验收 / 作废
> 仓库：D:\deepseekwork\neovim-cursor-pr
> 分支：<从 main 新建 xxx / 留在当前分支>
> 基线：已装 0.9.xxx（读 jar 内 plugin.xml）；HEAD 见 git log -1

## 1. 背景与证据
- 用户原话（逐字引用）
- 已核实的事实：日志行 / 配置现值 / jar 内版本 / 探针输出
- 尚未确认的假设（标注「待验证」）

## 2. 目标
一句话，可验证。

## 3. 非目标（明确不做）
防止执行会话扩大范围。

## 4. 允许改的文件
- src/main/java/...（列出具体类）
- tools/settings-probe/...（探针）
- 禁区：core/NeovideConfig.java（D0）、...
> 需要改清单外的文件时：停下问，不要自行扩大。

## 5. 验收标准（可测）
| 编号 | 标准 | 怎么验 |
|---|---|---|
| AC-1 | ... | 探针 X 断言 / 实机步骤 |

## 6. 必跑命令
（完整粘贴，不要写「见上文」）

## 7. 报告要求
按本文件「REPORT 模板」写，数字必须来自命令输出。

## 8. 禁止
- 不改断言方向（除非本章明确授权）
- 不装 jar / 不 push（除非本章明确要求）
```

## 四、REPORT 模板（执行会话写）

```markdown
# <主题> 执行报告（YYYY-MM-DD）

> 状态：待验收 / 已验收 / 部分完成 / 失败
> 提交：<hash 或「未提交」>　分支：...

## 1. 结论
一句话：做成了什么 / 没做成什么。

## 2. 根因
bug 类必填；功能类写「为什么这样改」。

## 3. 改动清单
| 文件 | 改了什么 | 为什么 |

## 4. 证据
- 命令 + 关键输出（不是「跑过了」）
- 门禁：V-PROBES RESULT: ...
- D0：零 diff
- 变异测试：改坏 X → 断言 Y 红 → 恢复全绿

## 5. 未验证 / 未覆盖
诚实列出（例：「recordFrameStats 无守门断言」）。

## 6. 阻塞与偏离
任何没按 PROMPT 做的点，逐条写原因；没有就写「无」。

## 7. 验收记录（用户填）
- 实机环境：IDE + 版本
- 结论：通过 / 不通过 + 现象
```

## 五、代理与技能怎么分工

| 阶段 | 点名用谁 | 注意 |
|---|---|---|
| 决策：出方案 | `planner` 或 `/plan` | 只读，不改代码 |
| 决策：查调用面 | `Explore` 代理 | 可并行；只读 |
| 决策：找现成实现 | `search-first` 技能 | 先搜再写 |
| 执行：写探针 | `tdd-workflow` 技能 | 判据以本项目探针 / 门禁为准 |
| 执行：修 bug | `docs/WORKFLOW.md` 第 1 步 | 全局点名的 `systematic-debugging` 当前不在可用技能列表，别硬点 |
| 执行：验证 | `verification-loop` + 全量门禁 | 门禁**不许并发**，两个代理也不行 |
| 提交前审查 | `java-reviewer` / `code-reviewer` | 只读；问题写进 REPORT，不直接改 |
| 交付 | `delivery-gate` + `/quality-gate` | 以项目门禁结果为准 |

**技能是流程提醒，不是判据。** 判据永远是：需求 + 探针 + 门禁 + 用户实机验收。

---

## 六、五条硬约束

1. 决策会话不写生产代码；执行会话不改验收标准。
2. PROMPT 必须自包含；执行会话不许要求「回上一个会话看」。
3. REPORT 里每个数字都要有命令出处；没有就写「未验证」。
4. 两个会话不得同时跑门禁（共用 `build\v2-probe\classes`，会假红）。
5. 验收没通过之前，PROMPT 不得标「已验收」，目录不得移入 archive。

---

## 七、发提示词前 / 交报告前的自检

**决策会话**：

- [ ] 用户原话逐字引用
- [ ] 每条「已核实」都有文件 / 行号或命令输出
- [ ] 非目标写了
- [ ] 允许改的文件列全，禁区写了
- [ ] 验收标准可测（能写探针，或能给出实机步骤）
- [ ] 必跑命令可直接粘贴

**执行会话**：

- [ ] 门禁最后一行是 `ALL PASS`
- [ ] D0 零 diff
- [ ] 新行为有守门探针 + 变异测试
- [ ] 偏离 PROMPT 的地方都在 §6 写了
- [ ] 未验证项没有藏
