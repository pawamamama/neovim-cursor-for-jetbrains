## 一、用户决策（逐条）

### 1. 光标行手感页：预览窗左移，尺寸组放到它旁边

**用户原话**：

> 光标行手感里面的，光标尺寸颜色效果可以放到动画预览窗口旁边，能放开，
> 左移窗口就行了而且也够

**现状**：组「单行输入输出（打字 / 退格）」里是「预览窗在上、滑块在下」；
组「光标（尺寸 / 颜色效果）」是**另一个组**，垂直堆在页面更下方。

**目标**：把「光标宽度」「光标高度」挪到预览窗**右边**，与预览窗并排。
预览窗左移即可腾出右侧空间。

**理由**：标签页里横向有富余，垂直堆叠让用户调「光标宽度」要往下滚很远，
而它其实和打字观感直接相关。

## 四、与代码审查的关系：先重构，后审查

**顺序：重构 → 审查。**

理由：

1. 重构会重写大量 `build*Group()` 方法，先审这些即将被推翻的代码是浪费。
2. 这三条问题都是用户**使用中看出来的**，不需要审查来发现。
3. 重构完再审，审的是最终形态，报告行号不会因后续重构失效。

审查范围不变：`ui/settings/` 8 文件 5463 行（全量第 3 批）。

## 五、探针契约影响（重构必读）

改控件会触发下面这些断言，**全部是契约变更，不是缺陷**：

| 探针 | 断言 | 什么会触发 |
|---|---|---|
| `VAddSetting.java:115` | `sliders == 14 && checks == 9 && combos == 4` | 加/减任何控件 |
| `VerifyPanel.java:97 / 104 / 108` | 同上三个数 | 同上 |
| `VTabPages` 的 `EXPECTED_COMPOSITION` | 每页控件构成表 | 改某一页的控件构成 |
| `VUi.KEYS` / `VUi.SPEC` | 控件渲染顺序与量程 | 新增/删除滑块 |

**最容易出错的是 `VUi.KEYS` 的插入位置**：它的顺序是「面板真实渲染顺序」，
新控件**必须插到它实际渲染的位置**，追加到末尾会让下游探针**静默测错字段**
（`CLAUDE.md` §7.0 C 记录的 0.9.79 事故）。

正确做法：改这些常数并在旁边写「契约变更，非缺陷」——**不许反过来动生产代码迁就断言**。
