# 演示视频脚本

> 状态：脚本阶段，**效果视频暂不录**（用户 2026-10-25 决定）。
> 本文只定义「拍什么、怎么拍、拍完剪成什么样」，不依赖任何未实现的功能。

---

## 一、先说结论：这个产品难拍

光标拖尾是**亚像素级、高帧率、局部小范围**的运动。拍不好会变成三种废片：

| 拍法 | 结果 |
|---|---|
| 全屏录屏 + 压缩 | 拖尾糊成一团，看不出形状 |
| 只截光标附近 | 看不出它在写代码，像抽象动画 |
| 正常速度播放 | 观众看不出「斜」和「不斜」的区别 |

**所以脚本的核心是「同时给两种视角」**：左边真实代码区（看得出在打字），
右边光标特写（看得出形状），中间用一条线连起来。

---

## 二、必须先解决的三个技术问题

### 1. 高帧率录制

拖尾动画 125fps，普通录屏 30/60fps 会丢帧。

可行方案（按推荐度）：

| 工具 | 帧率 | 说明 |
|---|---|---|
| **OBS + 显示器采集** | 60fps 稳 | 免费、稳。够用，但要降速播放 |
| **Windows 游戏栏 (Win+G)** | 60fps | 系统自带，零成本 |
| **IDEA 自带录屏** | 不可控 | 不建议 |

**关键技巧：60fps 录制 + 后期降速到 0.25x**，等于 240fps 的观感。
这比追求高帧率录制可靠得多。

### 2. 光标特写怎么拍

两种做法：

**A. 屏幕放大（推荐）**
- IDEA 设置里把字号调到 30+（`Settings → Editor → Font`）
- 光标宽度调成 5px（插件设置里可调）
- 录制区域只框一小块
- 优点：零额外工具，真实渲染

**B. 后期裁切放大**
- 正常录制全屏，后期在剪辑软件里把光标附近裁出来放大 4-8 倍
- 优点：一次录制可出多种镜头
- 缺点：放大后可能有锯齿（取决于录制码率）

**建议：两个都拍**。A 做主镜头，B 做补充。

### 3. 「斜」和「不斜」的对比怎么表现

这是脚本最核心的一幕。单纯展示「斜」观众不知道你在说什么。

**做法：并排对比 + 同步动作**

```
┌─────────────────┬─────────────────┐
│  斜度 0%（矩形） │  斜度 100%（上游）│
│                 │                 │
│   [光标录入]     │   [光标录入]     │
└─────────────────┴─────────────────┘
        ↑ 同时打同一段字
```

实现方式：开两个 IDEA 窗口，一个设斜度 0、一个设 100，
用宏工具（AutoHotkey）向两个窗口同时发同一串按键，录屏。

## 三、分镜脚本

### 开场（0:00–0:08）

**画面**：黑底，白色文字逐字出现

```
你的 IDE 光标
一直是「跳」的
```

**旁白**：无（文字自己说）。

**为什么这样开场**：不要品牌露出、不要 logo 动画。
观众划到视频只有 1 秒决定要不要继续看，先给「痛点」或「反常识」。

---

### 场景 1：对比（0:08–0:20）

**画面**：左右分屏

```
┌─────────────────┬─────────────────┐
│  原生光标        │  装了插件        │
│  （一段代码）    │  （同一段代码）  │
│                 │                 │
│  光标瞬移        │  光标滑过去      │
└─────────────────┴─────────────────┘
```

**动作**：两边同时按方向键移动 5 个字符。原生瞬移，插件滑行。

**后期**：降速到 0.3x。不降速看不出差别。

**旁白**：「左边是原生，右边是装了插件的。同一段操作。」

---

### 场景 2：拉伸（0:20–0:35）

**画面**：右侧光标特写（放大 6 倍），左侧代码区同步显示

**动作**：连续打出 `hello world`（约 10 个字符，每字 150ms）

**后期**：光标特写区右下角加一个实时数值「拉伸 8.3px」。
这个数字是实测的，不是编的（`docs/PERFORMANCE-FPS.md` 有数据）。

**旁白**：「打字的时候，光标不是整体移动，是**先拉开、再收回**。
拉开的最大幅度约 8 像素。」

---

### 场景 3：斜度对比（0:35–0:52）★ 核心

**画面**：左右分屏，都是光标特写（放大 6 倍）

```
┌─────────────────┬─────────────────┐
│  斜度 0%         │  斜度 100%       │
│  规整矩形        │  平行四边形       │
│  只伸缩不倾斜    │  向左上倾斜       │
└─────────────────┴─────────────────┘
```

**动作**：两边同时打 `function test() {`（同步按键）

**后期**：降速 0.25x。在两者之间加一条虚线标注「倾斜 4.06px」。

**旁白**：「同样是拉伸，斜度 0 是规整矩形，斜度 100 会倾斜。
这就是 Neovide 原版的手感。」

**这一幕为什么重要**：它同时展示了「功能存在」和「可调」两个卖点。

---

### 场景 4：删除方向相反（0:52–1:02）

**画面**：光标特写，先打字再退格

**动作**：
1. 打 `abcdef`（右移，向左拖尾）
**停顿 0.5 秒**
2. 退格 3 次（左移，向右拖尾）

**后期**：两个动作之间加文字标注「方向反过来了」。

**旁白**：「删除的时候方向相反——这就是为什么它看起来像有惯性。」

---

### 场景 5：跨行缎带（1:02–1:14）

**画面**：代码区，光标从一行末尾跳到下一行开头

**动作**：按 Enter 换行

**后期**：降速 0.2x，光标特写加标注「跨行是另一套时长」。

**旁白**：「换行用的是另一套动画时长，会更长一点，像缎带甩过去。」

---

### 场景 6：RGB（1:14–1:26）

**画面**：光标特写，颜色在流动

**动作**：静止不动（让色相自己转），然后打几个字

**后期**：不要加任何特效。颜色本身够抢眼。

**旁白**：「还有一个彩虹模式。静止的时候颜色也在流动。」

**注意**：这一幕最容易显得「土」或「廉价」。
如果成品看起来廉价，**直接删掉这一幕**——它不影响主线说服力。

---

### 场景 7：参数面板（1:26–1:40）

**画面**：设置面板，鼠标拖动滑块

**动作**：拖「斜度」滑块 0 → 100，右侧预览窗跟着变

**后期**：加速到 2x（面板操作本身很慢）。

**旁白**：「所有参数都能调，右边有实时预览。」

---

### 收尾（1:40–1:50）

**画面**：黑底 + 文字

```
免费 · 开源
github.com/pawamamama/neovim-cursor-for-jettbrains
```

**旁白**：无。

**为什么不要口播 CTA**：「点赞关注」会显著降低技术视频的可信度。
给链接，观众自己决定。

## 四、录制清单（照着打勾）

### 准备

```
[ ] IDEA 字号调到 30（Settings → Editor → Font）
[ ] 光标宽度调成 5px（插件设置）
[ ] 屏幕分辨率固定，录制全程不变（避免后期缩放不一致）
[ ] 关闭所有通知（Windows 专注助手）
[ ] 关闭 IDEA 的拼写检查波浪线（干扰视线）
[ ] 准备一段固定代码（每次录制用同一段，便于剪辑对齐）
```

### 录制参数

```
分辨率     1920x1080（不要 4K，剪起来卡）
帧率       60fps
码率       20 Mbps 以上（拖尾细节多，低码率会糊）
格式       MKV（中断也不丢文件），后期转 MP4
```

### 每个场景单独录一个文件

**不要一口气录完**。分开录的好处：
- 某个场景拍砸了只需重录那一个
- 剪辑时直接按文件名排序拼接

命名：`01-compare.mp4`、`02-stretch.mp4`、`03-slope.mp4` …

## 五、后期要点

| 项 | 做法 |
|---|---|
| 降速 | 所有光标特写镜头降到 0.25x；代码区全景保持 1x |
| 标注 | 用细线 + 小字，**不要用大箭头和爆炸贴纸** |
| 数值 | 只标实测值（8.26px / 4.06px / 125fps），不要凑整 |
| 转场 | 硬切。不要用任何转场特效 |
| 音乐 | 可选。如果要，选无旋律的氛围音（低频铺底），音量压到 -25dB 以下 |
| 时长 | **控制在 2 分钟内**。超过 2 分钟完播率断崖 |

## 六、我建议的另一种形态（也许更好）

如果上面这套拍起来太麻烦，还有个更省力、传播性更强的做法：**只做 GIF**。

| | 视频 | GIF |
|---|---|---|
| 制作成本 | 高（分镜、剪辑、配音） | **低**（一段录屏转 GIF） |
| 观看门槛 | 需要点播放 | **自动循环播放** |
| 适合场景 | 官网首页、B 站 | **README、GitHub、推文** |
| 能表达的 | 完整叙事 | **单一特征** |

**推荐做法**：

做 3 个独立 GIF，各 2-3 秒，放在 README 里：

```
gif/1-stretch.gif    打字时先拉后收（斜度 100）
gif/2-slope.gif      斜度 0 vs 100 并排
gif/3-crossline.gif  换行缎带
```

一个 GIF 只表达一件事，看完就懂。这比 2 分钟视频**传播效率高得多**。

视频留给「有人已经在用、想深入了解」的时候再拍。
