## 需求一：RGB 光标绘制

### 我诚实的判断：**当前架构下价值很低**

**理由（技术事实）：**

```
光标宽度 2px（IDEA 默认）
渐变需要「空间」才能显示出来
2px 宽的竖条上做横向渐变 = 只有 2 个像素，看不出任何渐变
```

**唯一有意义的方向是「纵向渐变」**——沿拖尾长度（拖尾会拉长到 10~40px）。

**所以 RGB 只有在「光标变宽之后」才真正有用。**
这与你第二个需求（宽度最大 5px）是同一件事 —— **先做宽度，RGB 才有意义。**

### 技术上可行（实测过）

```java
// CaretTrailPanel.java:454-455 唯一填充点
g2.setColor(fillColor);
g2.fill(path);

// 改成：
g2.setPaint(new GradientPaint(x1, y1, c1, x2, y2, c2));
g2.fill(path);
```

**只有一处**，改动量小。但需要：
- 配置项（起止色 / 方向 / 是否跟随拖尾年龄）
- `NeovideConfig` 是新字段 → 受 D0 保护（D0 只守文件 diff，加字段要慎重）

### 建议

| 选项 | 说明 |
|---|---|
| **A** | 今晚只做**最小可运行案例**（硬编码两色纵向渐变），验证绘制可行 |
| **B** | 等宽度功能做完再做 RGB（那时才有视觉收益） |

**我倾向 A**（你说过「先做简单运行案例」），但要清醒：**现在看不出效果是正常的，不是做错了。**

## 需求二：光标自由大小

### 你给的规格

```
最大长度 = 目前的长度（顶格 = 行高）  ← 不能超过
宽度最大 5px（IDEA 原光标宽度）
静止时也保持这个大小
扩散辉光根据矩形大小调整
自动适配当前字体 —— 【明天做，今晚不做】
```

### 当前实现（已查证）

```java
// CaretAnimator.java:1245-1258
int realCursorWidth = -1;
realCursorWidth = EditorUtil.getDefaultCaretWidth();   // 像素，IDEA 真值
realCursorWidth = ratio;                                // 兜底
```

**宽度来源已经有了，只是没暴露成可调项。**

### 关键约束：静止时必须一样大

**这是个容易踩的坑**：拖尾静止时会收缩到「理论矩形」。
所以「用户设 3px」必须在**静止帧**也读 3px，不能只在运动帧。

**已验证的实现方式**：现有 `setTarget(cx, cy, w, h)` 每帧都传尺寸，
只要 `w` 来自用户设置而非默认值，静止时就是那个尺寸。

### 辉光半径要跟着矩形走

```java
// CaretTrailPanel.updateGlowRadius()
double maxDim = Math.max(cursorWidth, cursorHeight);
float newWidth = (float) (config.shadowBlurFactor * maxDim);
```

**已经按矩形算了**，不用改。只要传对尺寸，辉光自动适配。

## 需求三：纯平滑输入为什么「不倾斜」

### 结论：**不是 bug，是参数使然**

### 倾斜的几何原理

```
四个角各有时长 → 到达目标的时刻不同 → 中间态是平行四边形
时长差越大 → 倾斜越明显
```

### 实测数据

| 预设 | k | trailFactors | 最大/最小 | 倾斜度 |
|---|---|---|---|---|
| 基础 | 4.5 | `[1.00, 0.72, 0.42, 0.22]` | **4.5×** | 明显 |
| 缎带 | 8.0 | `[1.00, 0.69, 0.35, 0.13]` | **7.7×** | 最明显 |
| **纯平滑输入** | **2.0** | `[1.00, 0.82, 0.63, 0.50]` | **2.0×** | **几乎不斜** |

**「纯平滑输入」的 k=2.0 让四角时长趋同 → 矩形几乎不变形 → 看起来不倾斜。**

### 那这个名字对吗？

**名不副实。** 它的实际效果是「四角同步平移」，而不是「平滑地拉出斜角」。

**Neovim 原版没有这个概念** —— `trailSize` 只管前缘/后缘两档，
`typingSmoothness` 是本插件自创的（见代码注释「那是本插件早期自创的」）。

### 三种可能的处理

| 选项 | 说明 |
|---|---|---|
| **A** | 改名为「四角同步（无明显斜角）」—— 诚实反映行为 |
| **B** | 调高 k（如 3.5）让它也有斜角 —— 但那就和「基础」重复了 |
| **C** | 删掉这个预设（只剩 2 个） |

**我倾向 A**：行为没问题，名字误导。
