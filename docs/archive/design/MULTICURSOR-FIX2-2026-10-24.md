## 二、问题 1：中文不支持（已修）

### 根因

块选区的 key 用了 `blockStarts[i]`（**offset**）。

输入中文后，**每行的 offset 都会变**（多了一个字符）→ key 变化 →
被当成「新光标」→ 每帧重建 `SpringTrail`：

- 旧拖尾被丢弃 → 其他行「不动」
- 新拖尾走 `startFrom` → 「重定位」的观感
- 只有最后一行看起来正常

### 修法

key 改用 **行号**（行内编辑时行号不变，只在真正增删行时才变）。

## 三、问题 2：撕裂/串扰（已修）

### 根因

`tickSpring` 里 `maxOffset` 取**所有光标的全局最大值**，同时驱动：
- `lastGlowStrength` 记录
- `fading` 判断

于是**一个光标在动，会拉长所有光标的辉光淡出**。

### 修法：相邻行分组

按你的原话实现：「假如 123 行是在一起的，5 行独立一个」：

```java
public static int[] groupAdjacentLines(int[] lines)
// 相邻行（差 ≤ 1）归为一组
```

同组共享组内最大偏移（视觉上是一个整体），**组间互不影响**。

## 四、问题 3：拖尾长度不一致（已修）

### 根因

块选区第一版让所有新光标都 `startFrom(最近的光标)`。
而 `startFrom` 是「**复制源的当前形状**」—— 源在 (x0,y0)、新光标在 (x0,y1)，
复制过来的四角**相对自己目标点是错的**。

第一行先建、状态最新；后面几个复制到「陈旧形状」→ 长度不一致。

### 修法

块选区**不使用 `startFrom`**，各自吸附到目标（同时出现，不该有先来后到）。
普通多光标（逐个添加）仍保留 `startFrom`。

## 五、问题 4：辉光每个都发散（上游也如此）

查上游 v0.5.1 `pushQuads()`：

```java
float glow = (float) ((trail.maxOffset() - GLOW_FADE_START)
        / (GLOW_FADE_END - GLOW_FADE_START));
panel.addQuad(quadX, quadY, glow);   // ← 每个四边形独立 glow
```

**唯一差异**：上游**不 clamp 到 [0,1]**，我们 clamp 了。

所以「每个都发散」是设计如此，**不是 bug**。
本次通过分组让相邻行共享辉光，视觉上更整体。

## 六、问题 5：Alt+Shift+点击 测不出来

**这不是我们的 bug。**

`Alt+Shift+点击` 在 IDEA 里**不是默认快捷键**。你的配置里有
`EditorCloneCaretAbove` / `EditorCloneCaretBelow`，说明你用的是**克隆光标**快捷键。

想确认 `Alt+Shift+点击` 是否绑定：`Ctrl+Shift+A` → 搜 `Add Caret`。
