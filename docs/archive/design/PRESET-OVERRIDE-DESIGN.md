# 预设覆盖值设计（0.9.8 第一件）

> 触发：用户实测「改成原版粉色（已修改）→ 切到缎带 → 再切回来，已修改没了，坍缩回干净预设」。
> 根因：预设是**常量表**，切换就整组覆盖，**用户的改动没有落脚点**。

## 1. 目标模型：每个预设各自记住自己的改动

```
用户改「原版粉色」的辉光层数 → 只影响「原版粉色」
切到「缎带」→ 用缎带的值（缎带是干净的）
切回「原版粉色」→ 回到用户改过的值，名字仍是「原版粉色（已修改）」
点「恢复为「原版粉色」默认值」→ 清掉这份覆盖，回到干净常量
重启 IDEA → 覆盖与「已修改」状态都还在
```

## 2. 存储（持久化）

- 新增一个持久化字段：`String animPresetOverrides`
- 格式（可解析、可演进）：`0=0.10,0.11,1.00,3,0.20,0.55;3=0.28,0.11,1.00,8,0.20,0.55`
  键 = 预设下标；值 = 预设定义的那 6 个字段（anim, short, trailSize, layers, blur, glowOpacity）
- 空字符串 = 没有任何覆盖（新装用户就是这个状态 → 全部干净，没有「已修改」）
- **只存预设域 6 个字段**；其余 13 个（总开关组 / 颜色 / 拉伸强度 / 输入平滑 / 不透明度 / 辉光开关）
  从来不属于预设，改它们永远不影响「已修改」

## 3. 与现有字段的关系

- `animPresetBase`：保留，表示“当前停在哪一个预设”。
- 「已修改」的判定：当前 6 个值与**该预设的常量**逐项比对（≠ 常量 ⇒ 已修改）。
  ⚠️ **实施修正（见 0.9.8-TASKS.md §6）**：本节原文写的是「与 overrides[base]（有则用）比对」——
  那样「切回改过的预设」时当前值 == 覆盖值，会被判成「未修改」，与 M5-13 直接矛盾。
  最终语义：**基准**用有效值（覆盖??常量）判，**「已修改」**用常量判。
- 基准是谁：当前值 == 有效值(基准) 时**不东移**基准（挡住「改出来的值恰好等于另一个预设常量」把基准抢走）。
- 切预设：`pending = overrides[idx] ?: preset.constants`，并把 `animPresetBase = idx`。

## 4. UI 要说清的两件事（用户反馈：不知道哪个是持久参数，很可怕）

1. **全部 19 个参数都持久化**（都在 `NeovideCursorSettings.xml`）。「不随预设变化」只是**语义分组**，不是“不保存”。
2. 面板把 4 个不参与预设的字段**集中成一组**，组标题写清楚：
   `全局设置（不随预设变化，但会保存）`
   成员：拖尾拉伸强度、输入平滑、拖尾不透明度、启用辉光。
   —— 比现在“每行标签加个括号”清楚得多（用户原话：用户也不知道哪个是哪个）。

## 6. 验收断言（新增 M5-13..M5-16）

- M5-13 改原版粉色 → 切缎带 → 切回：值恢复成改过的，名字仍是「（已修改）」
- M5-14 重启（新建 Configurable）后仍保持覆盖
- M5-15 点「恢复默认」→ 覆盖被清掉，名字变干净
- M5-16 不参与预设的 4 个字段改动**不**产生覆盖（预设名不变）
