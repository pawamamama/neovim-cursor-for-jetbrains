## 一、你说的问题

> 「相邻行合并我说是多行统一一个矩形你明白吗，而且 6 行的话前三个走的慢
> 后三个走得快，就是拉伸的时候列不一致也不像原版 vscode 那样是一整个斜阶梯，
> 我们是不一致的」

**我之前理解错了。** 你说的是「多行统一成**一个**矩形」，
我做的是「相邻行分组共享辉光，但每行仍是独立的四边形」。

---

## 二、第一版错在哪

块选区被展开成 **N 个独立 SpringTrail**（每行一个）。

每行的四角弹簧状态各不相同（初始吸附时刻、maxOffset 都不同），于是：

| 现象 | 原因 |
|---|---|
| 前三个慢、后三个快 | 各行弹簧的 animationLength 与残余速度不同 |
| 列偏移不一致 | 各行独立推进，斜度各自演化 |
| 不是斜阶梯 | 视觉上是 N 个竖条，不是一个平行四边形 |

---

## 三、修法：块选区 = 1 个 SpringTrail

块选区在语义上是**一个矩形区域**，就该用**一个**拖尾：

```java
// 新增：计算整体包围盒
public static double[] blockSelectionBounds(int[] starts, int[] ends,
                                            double charWidth, double lineHeight)
// 返回 [minX, minY, maxX, maxY]
```

| 改动 | 前 | 后 |
|---|---|---|
| 拖尾数量 | N（每行一个） | **1**（整体） |
| 目标尺寸 | 单字符 `(width, height)` | **整个矩形** `(targetW, targetH)` |
| 拉伸行为 | 各行独立 | **整块一起拉成平行四边形** |

---

## 四、代码审查发现的第 3 个缺陷

**块选区的 key 用了「选区首行行号」。**

用户 `Alt+向上拖拽` 扩大选区时，**首行会变** → key 变 →
被当成新光标 → 重建 `SpringTrail` → 拖尾跳变。

**修法**：改为固定常量 `BLOCK_SELECTION_KEY`。
块选区恒为 1 个拖尾，key 本就不该变 —— 这恰恰是「同一个矩形在拉伸」的前提。
