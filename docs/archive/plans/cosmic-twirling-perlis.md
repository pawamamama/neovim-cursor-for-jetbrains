### 1. `docs/HANDOFF-FADE-2026-11-02.md`

内容大纲：

- 当前状态：已装 0.9.124；工作区代码是 0.9.125（未提交）；dist 保留 0.9.124 / 0.9.125；文档仍写 0.9.120；
  PyCharm 0.9.113；D0 零 diff；门禁全绿。
- 版本行为对照表（≤0.9.117 / 0.9.118~120 / 0.9.121 / 0.9.122 / 0.9.123 / 0.9.124 / 0.9.125），
  每一版的计时起点、展开期亮度、用户反馈。
- 已确认的根因：
  1. `4af8965`（0.9.118）把淡出计时绑到 `moved` → 跨行 120ms 后辉光归零（实测 72% 拖尾无光）；
  2. 旧版（≤0.9.117）淡出起点亮度只有 1.5%（报告 §14.2），所以「淡出」肉眼不可见；
  3. 0.9.123 在收拢帧把保持值从 ≈0.02 钉到 1.0 → 次帧跳变 = 用户说的「闪两下」；
  4. 光晕贴着四边形绘制，四边形收拢时光晕**面积**骤缩，所以 75ms 的 alpha 淡出仍显突兀。
- 已试过并否决的方案（避免重来）：0.9.120（满亮撑到停 + 跨行中途灭）、0.9.121（停下后才灭）、
  0.9.122（无尾巴、变快）、0.9.123（闪灯）、按层数递减（8 档跳变，用户认为改手感）。
- 探针与变异的真实记录（含 P-6 假通过的教训：预览跨行驱动无法可靠隔离单次动作）。
- 已知未覆盖面：生产的短跳行为目前只有源码守卫（T-22 类），没有动态探针；
  多光标相邻行同组共享辉光（既有设计，无探针）。
- 待用户拍板的方向 A/B/C（A 只调参数、B 限速变暗、C 按层数）。
- 建议的 B 方案实现草图：亮度目标仍为 `strengthFor(offset)`；下降速度上限 = 1/淡出时长；
  完全收拢后先等保持时长再继续；按组维护状态；调度直到归零。
